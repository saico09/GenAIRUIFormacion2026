## HDU-002 · 27/10/2026 · Crear y consultar tres pacientes en FastAPI

Planificada para el 28/10; se adelantó al 27/10 a pedido de Marco.

### Tabla public.patients (creada por FastAPI al arrancar)

```text
   Column   |          Type          | Nullable |             Default
------------+------------------------+----------+----------------------------------
 id         | integer                | not null | generated by default as identity
 name       | character varying(200) | not null |
 birth_date | date                   | not null |
 email      | character varying(320) | not null |
Indexes: "patients_pkey" PRIMARY KEY, btree (id)
```

Conexión: `app/db.py` arma la URL con POSTGRES_HOST, POSTGRES_DB, POSTGRES_USER y POSTGRES_PASSWORD (variables de entorno que pasa compose.yml desde .env).

### Validaciones -> 422 (antes de cargar datos; la tabla quedó con 0 filas)

```text
name "   " (vacío)           -> 422  body.name: String should have at least 1 character
birth_date "2026-02-30"      -> 422  body.birth_date: day value is outside expected range
birth_date "10-01-1990"      -> 422  body.birth_date: debe ser texto con formato YYYY-MM-DD
birth_date 0 (número)        -> 422  body.birth_date: debe ser texto con formato YYYY-MM-DD
email "sin-arroba"           -> 422  body.email: An email address must have an @-sign.
sin email                    -> 422  body.email: Field required
select count(*) -> 0
```

Corrección durante la prueba: con `Field(strict=True)` en birth_date también se rechazaba la fecha válida "1990-01-10"
(FastAPI valida en modo Python y strict solo acepta objetos date). Se reemplazó por un validador previo que exige el formato YYYY-MM-DD.

### POST /patients con datos/pacientes.json (PowerShell, comando de GUIA.md)
